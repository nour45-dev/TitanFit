## 🏢 د) تدقيق عزل الأندية والهوية البصرية (White-Label Isolation)

1. **عزل الهوية:** تخصيص ألوان وشعار المستأجر A (مثل اختيار اللون الزمردي أو شعار النادي) يتم تطبيقه على سياق النادي A فقط.
2. **عزل المتدربين:** قائمة متدربي النادي A وأكواد اشتراكاتهم مفصولة تماماً عن بيانات النادي B.
3. **تنبيه العزل المعماري:** العزل حالياً يدار عبر حالة الذاكرة المحلية (Client Mock State)؛ ويتم نقله إلى PostgreSQL RLS التام في **PR 1 (ADR 0001)** لمنع أي تسريب على مستوى الشبكة.

## 🚫 ح) قائمة الضغطات الميتة والأزرار الشكلية (Dead Clicks & UI Stubs)

خلال الزحف والتفاعل، تم حصر الأزرار وعناصر التحكم التي تعمل كـ Stubs أو واجهات شكلية بدون ربط حقيقي:

1. **زر "طباعة / حفظ كملف PDF" في تفاصيل الفاتورة:** يستدعي أمر المتصفح للطباعة `window.print()` بدلاً من توليد فاتورة PDF رسمية موثقة بختم ضريبي.
2. **أزرار الدفع الإلكتروني المصري (Fawry / Paymob / InstaPay):** تفتح نماذج تفاعلية تحاكي السداد وتنشئ إشعاراً محلياً، دون اتصال حقيقي بـ Gateways السداد المالي (مقصودة لحماية البيئة من أي دفع حقيقي).
3. **تكامل قارئ الباركود للبوابات الفيزيائية (Hardware Turnstile Relay):** زر "مسح تجريبي" يحاكي تمرير العضو عبر كود داخلي، دون وجود Socket موصول ببوابات إلكترونية فعلية (Turnstiles).
4. **تصدير التقارير المالية كـ CSV:** يولد ملف نصي تجريبي بالمتصفح، ولا يتصل بخادم التقارير المركزية.

## 🔍 ط) ما لم يتم اختباره في هذه الجولة (Uninspected Scope)

1. **التحميل اللحظي المتزامن (Concurrency & Load Stress):** لم يتم اختبار دخول مئات المتدربين في نفس الثانية عبر بوابات الجيم.
2. **تسليم رسائل الـ SMS / WhatsApp OTP الحقيقية:** تم اختبار واجهة الـ Interface فقط بدون الربط الفعلي بمزودي الاتصالات في مصر لتفادي تكلفة إرسال الرسائل واستهلاك الرصيد.
3. **طابعات الإيصالات الحرارية (Thermal POS Receipt Printers):** لم يتم ربط المنصة بطابعة إيصالات حرارية عبر منفذ USB/Bluetooth.
4. **الربط مع المنظومة الضريبية المصرية (E-Receipt ETA Integration):** الفواتير داخلية ولا ترسل لمنظومة الفاتورة الإلكترونية الحكومية.
