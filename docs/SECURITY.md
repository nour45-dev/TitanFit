# TitanFit — OWASP Top 10 & ASVS Level 2 Security Checklist (`SECURITY.md`)

| OWASP Category / ASVS Control | Implementation in TitanFit | Verification Test |
| :--- | :--- | :--- |
| **A01: Broken Access Control & Multi-Tenancy** | • Permission-based `@RequirePermissions(...)` guard (deny by default; zero hardcoded role checks).<br>• PostgreSQL `FORCE ROW LEVEL SECURITY` with `gymos_app` (`NOSUPERUSER NOBYPASSRLS`).<br>• Tenant-prefixed S3/R2 object keys (`tenants/<tenantId>/...`). | `packages/database/src/rls-role.spec.ts`<br>`apps/api/src/platform-phases.spec.ts` (Phase 1.3 & 1.4)<br>`apps/api/src/health.spec.ts` |
| **A02: Cryptographic Failures** | • Passwords hashed with memory-hard `scrypt` ($N=16384, r=8, p=1$, 16B random salt).<br>• Member health records encrypted at rest using **AES-256-GCM** with per-record 12B IV, 16B auth tag, and `tenantId` bound as Additional Authenticated Data (AAD). | `apps/api/src/platform-phases.spec.ts` (Phase 2.1) |
| **A03: Injection & Input Validation** | • Strict Zod schemas in `@gymos/contracts` validating all body/query inputs.<br>• Parameterized Prisma queries only. | `packages/contracts/src/contracts.spec.ts` |
| **A04: Insecure Design (Passback & Double-Charge)** | • 30-second rotating HMAC-SHA256 QR tokens (`TITANFIT:v1:...`) + 15-minute anti-passback cooldown.<br>• Mandatory `Idempotency-Key` support on subscription purchases. | `apps/api/src/platform-phases.spec.ts` (Phase 2.2 & 3.2) |
| **A05: Security Misconfiguration** | • Fail-fast Zod startup environment validation (`validateApiEnv`, `validateWebEnv`).<br>• Fastify Helmet CSP + Next.js HSTS, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`.<br>• `/api/v1/ready` returns `503` if DB user has `SUPERUSER` or `BYPASSRLS`. | `packages/config/src/config.spec.ts` |
| **A07: Identification & Authentication Failures** | • Progressive brute-force account lockout after 5 failed attempts.<br>• Refresh token family rotation with automatic reuse detection (replay revokes entire token family).<br>• Optional RFC 6238 TOTP 2FA and 6-digit OTP with attempt limits. | `apps/api/src/platform-phases.spec.ts` (Phase 1.1 & 1.2) |
| **A08: Software & Data Integrity Failures** | • Paymob HMAC-SHA512, Fawry SHA-256, and Stripe webhook signature verification using `timingSafeEqual`.<br>• Automated pre-commit & CI secret scanner (`infra/scripts/secret-scan.mjs`). | `apps/api/src/platform-phases.spec.ts` (Phase 2.3) |
| **A09: Security Logging & Monitoring Failures** | • Structured JSON logging (`pino`) with secret/cookie redaction.<br>• Append-only `audit_logs` protected by PostgreSQL trigger `trg_audit_logs_immutable` blocking `UPDATE` and `DELETE`. | `packages/database/src/rls-role.spec.ts` |
